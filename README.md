# Regime — запильно или безоткатно (Tiger.com Windows, v0.1)

Два индикатора в одной сборке `RegimeMeter.dll`:

- **Regime** (`Z_Regime`) — отдельная панель под графиком, две линии режима;
- **Regime Shade** (`Z_RegimeShade`) — необязательная полупрозрачная подсветка
  баров прямо на графике цены, чтобы режим ловился боковым зрением.

Ставятся независимо. Расчёт у них общий, настройки дублируются — держите
одинаковые `k` и пороги.

## Что считается

Окно из **k баров графика** играет роль одной «старшей свечи», сами бары —
«младших». Дальше два отношения:

```
ER = √k · |C[i] − C[i−k]| / Σ|ΔC|     безоткатность: чистый ход против длины пути
RR = √k · (HH − LL) / Σ TR            размах «старшей свечи» против суммы «младших»
```

`ER` — это нормированный Efficiency Ratio Кауфмана, `RR` — нормированный
Choppiness Index наоборот. Обе считаются по последним k барам, включая текущий
формирующийся, — значение живое.

**Про √k.** Без нормировки отношение показывало бы в основном сам масштаб:
у случайного блуждания длина пути растёт как `k`, а смещение и размах — как `√k`,
так что «старшая свеча всегда меньше суммы младших в ≈√k раз» — это не сигнал,
а арифметика. Множитель `√k` это убирает, и остаётся только то, что интересно:

| Значение | Что это         | Что происходит на цене |
|----------|-----------------|------------------------|
| ≈ 1.0    | случайное блуждание | обычный шум, ни туда ни сюда |
| > 1      | безоткатно      | бары складываются в одну сторону, откаты мелкие |
| < 1      | запил           | путь длинный, прогресса нет, цена топчется |
| √k       | потолок шкалы   | движение строго в одну сторону, бары не перекрываются (k=12 → 3.46) |

Калибровка проверена тестами: на смоделированном случайном блуждании с честным
внутрибаровым ходом средний ER = 0.98, средний RR = 1.05; на чистом тренде
ER = √k ровно; на зигзаге ER = 0, RR = 1/√k.

**Зачем две линии.** ER смотрит на закрытия (направление), RR — на диапазон
(размах). Расхождение информативно:

- ER высоко, RR высоко — чистый импульс, тренд без откатов;
- ER низко, RR высоко — крупные качели широким диапазоном, но без прогресса
  (самое опасное место: волатильность есть, направления нет);
- оба низко — вялый флет;
- ER высоко, RR низко — редкость: ровное ползучее движение узким каналом.

## Как читать панель

- Сплошная горизонталь — **уровень 1.0** (случайное блуждание).
- Пунктир — пороги «запил» / «безоткатно».
- Толстая линия — ER, тонкая — RR.
- Заливка между ER и 1.0: зелёная выше верхнего порога, красная ниже нижнего.
- Строка в углу: `k12  ER 1.42  RR 1.18  ▲ безоткатно`.
- Под курсором и на шкале справа — текущие значения обеих метрик.

## Пороги: настройте под инструмент

Дефолты **0.85 / 1.20** — отправная точка, а не истина. На минутках крипты ER
обычно живёт чуть ниже единицы: микроструктура даёт возврат к среднему, спред
и дискретность шага «съедают» направленность. Посмотрите панель на своём
инструменте и таймфрейме полдня и сдвиньте пороги так, чтобы:

- нижний порог отсекал примерно нижнюю четверть значений,
- верхний — примерно верхнюю четверть.

Тогда подсветка будет загораться на том, что реально выделяется, а не постоянно.

## Настройки

**Regime**

| Раздел | Параметр | По умолчанию |
|---|---|---|
| 1. Расчёт | Окно k | 12 |
| | Сглаживание EMA, баров (1 = выкл) | 1 |
| 2. Пороги | «Запил» — ниже этого | 0.85 |
| | «Безоткатно» — выше этого | 1.20 |
| 3. Вид | Линия ER / линия RR / заливка / строка состояния | вкл |
| | Толщина линии ER, px | 2 |
| | Цвета линий и заливок | янтарный / синий / зелёная и красная с прозрачностью |

**Regime Shade** — те же `k`, сглаживание и пороги, плюс «По какой метрике»
(ER / RR / обе — «обе» подсвечивает только там, где они согласны) и отдельные
переключатели подсветки трендовых и пильных участков.

`k` — это и есть «во сколько раз старше»: на M5 `k=12` = часовая свеча,
на M1 `k=15` = четвертьчасовая. Меньше 6 брать не стоит — оценка становится
шумной (`√k` мал, усреднять нечего).

## Сборка и установка

```
# Windows, из папки RegimeMeter
dotnet build -c Release
# или укажите путь к терминалу, если он не в Program Files (x86):
dotnet build -c Release -p:TigerDir="C:\Program Files\TigerTrade"
```

Получившийся `RegimeMeter.dll` положить туда же, куда кладутся остальные
кастомные индикаторы, и перезапустить терминал. В списке индикаторов появятся
**Regime** и **Regime Shade**.

**Перед первым запуском сохраните конфигурацию**: Файл → Конфигурация →
Сохранить. Если индикатор сломает загрузку чартов, восстановление — оттуда же
(см. историю с Liquidations 29.08.2026).

## Тесты

```
cd Tests
dotnet run
```

Гоняется без терминала и без Windows (API заменён заглушками в `Stubs.cs`).
Кроме математики там есть **прогон «десериализованного инстанса»**: объект
создаётся через `GetUninitializedObject`, дальше `CopyTemplate` и все сеттеры,
затем `Execute/Render/GetMinMax/GetValues/GetLabels`. Это ровно тот путь,
на котором 29.08.2026 чарты теряли привязку к инструменту.

## Что проверить на живом терминале

Математика покрыта тестами, а вот допущения про API подтверждены только по
документации и по коду соседних индикаторов. Смотреть
`Документы\TigerTrade\Indicators\regime.log` — там одна строка при старте:

1. **`close: ...`** — откуда взялись цены закрытия. Ожидается `Helper.Close`
   или `Helper.Price(<enum>.Close)`. Если написано `(H+L)/2 — Helper.Close
   не найден`, индикатор работает по серединам баров: ER выходит заниженным,
   пороги надо сдвинуть вниз. Скажите мне — добавлю прямой доступ.
2. **`GetY(double)`** — панельные примеры документации (`*Delta`,
   `*CumulativeDelta`) зовут его с `double`, а AvanpostSync на графике цены —
   с `decimal`. Если сборка ругнётся на `GetY`, значит перегрузки под `double`
   нет: тогда во всех вызовах `GetY(x)` дописать `(decimal)`.
3. **`Canvas.GetX(index)` — центр колонки** (по примеру `*Delta`:
   `new Rect(x - width / 2.0, ...)`). Если линия и заливка окажутся смещены
   на полбара — значит это левый край, уберу `- w / 2.0`.
4. **`IndicatorValueInfo(string, XBrush)` и `IndicatorLabelInfo(double, XColor)`**
   — сигнатуры взяты из примера `*Delta`. Ошибка сборки здесь чинится
   подгонкой аргументов.
5. **Частота пересчёта.** `Calculation = OnPriceChange`, полный пересчёт ряда
   троттлится 100 мс (`RegimeData.ThrottleMs`). Если панель подтормаживает
   на длинной истории — поднять до 250–300 мс.
6. **Прозрачность цветов.** Заливки заданы с альфой (55 и 28 из 255). Если
   палитра терминала альфу не отдаёт — скажите, сделаю отдельную настройку
   «непрозрачность, %».

## Потоки и деcериализация

- `DataProvider` и `Helper` трогаются только из `Execute()`, `Render()` и
  `GetMinMax()` — колбэков самого терминала. Никаких своих потоков и таймеров
  здесь нет вообще.
- `CheckNeedRedraw()` только сравнивает версии и обёрнут в `try/catch`.
- Инициализаторов полей нет, сеттеры пишут только своё поле (и гасят кэш
  кисти — это тоже запись поля), `RegimeData` и кисти ленивые.
- Ошибки в лог пишутся не чаще раза в 10 с на место возникновения.

## Что можно доделать

- Алерт при переходе в режим (`CheckAlert` у панельных индикаторов есть).
- Звук на переход «запил → безоткатно» — стыкуется со SpikeVoiceover.
- Второе окно (быстрое + медленное) на одной панели: видно, режим только
  начался или держится давно.
